Window Function: LAG() & Dense Calendar

Business Question: What is the Month-over-Month (MoM) admissions velocity and Year-over-Year intake trajectory?

Computes volume momentum without expensive self-joins. Employs GENERATE_SERIES to create an unbroken calendar grid, preventing LAG(1) from skipping inactive months in filtered subsets.

Source File: sql/13_time_trends.sql
Engine: PostgreSQL 14+
Execution Time: ~45ms
sql/13_time_trends.sql (Excerpt: Dense MoM Velocity) 
WITH calendar_grid AS (
    SELECT DATE_TRUNC('month', series_date)::DATE AS calendar_month
    FROM GENERATE_SERIES('2019-05-01'::DATE, '2024-05-01'::DATE, '1 month'::INTERVAL) AS series_date
),
monthly_metrics AS (
    SELECT 
        DATE_TRUNC('month', date_of_admission)::DATE AS admission_month,
        COUNT(admission_record_id)                   AS monthly_admissions,
        ROUND(SUM(billing_amount), 2)                AS monthly_billing_usd
    FROM healthcare.admissions
    GROUP BY DATE_TRUNC('month', date_of_admission)
),
dense_monthly AS (
    SELECT 
        cg.calendar_month,
        COALESCE(mm.monthly_admissions, 0)   AS monthly_admissions,
        COALESCE(mm.monthly_billing_usd, 0.0) AS monthly_billing_usd
    FROM calendar_grid cg
    LEFT JOIN monthly_metrics mm ON cg.calendar_month = mm.admission_month
)
SELECT 
    calendar_month,
    monthly_admissions,
    LAG(monthly_admissions, 1) OVER (ORDER BY calendar_month) AS prev_month_admissions,
    ROUND(((monthly_admissions - LAG(monthly_admissions, 1) OVER (ORDER BY calendar_month))::NUMERIC * 100.0 / 
           NULLIF(LAG(monthly_admissions, 1) OVER (ORDER BY calendar_month), 0)), 2) AS mom_admission_change_pct,
    monthly_billing_usd,
    LAG(monthly_billing_usd, 1) OVER (ORDER BY calendar_month) AS prev_month_billing_usd,
    ROUND(((monthly_billing_usd - LAG(monthly_billing_usd, 1) OVER (ORDER BY calendar_month)) * 100.0 / 
           NULLIF(LAG(monthly_billing_usd, 1) OVER (ORDER BY calendar_month), 0)), 2) AS mom_billing_change_pct
FROM dense_monthly
ORDER BY calendar_month;

Percentiles & Robust Central Tendency

Business Question: Which medical condition drives the highest average and median gross hospital billing?

Calculates true median billing using PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY billing_amount::DOUBLE PRECISION)::NUMERIC to avoid outlier skew, and evaluates cost-to-volume absorption ratios.

Source File: sql/06_conditions.sql
Techniques: CTE, PERCENTILE_CONT, NULLIF
sql/06_conditions.sql (Excerpt) 
WITH condition_metrics AS (
    SELECT 
        medical_condition,
        COUNT(admission_record_id)           AS encounter_count,
        SUM(billing_amount)                  AS total_billing_usd,
        AVG(billing_amount)                  AS avg_billing_usd,
        PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY billing_amount::DOUBLE PRECISION)::NUMERIC AS median_billing_usd,
        AVG(length_of_stay_days)             AS avg_los_days
    FROM healthcare.admissions
    GROUP BY medical_condition
),
totals AS (
    SELECT SUM(encounter_count) AS grand_total_encounters, SUM(total_billing_usd) AS grand_total_billing_usd
    FROM condition_metrics
)
SELECT 
    cm.medical_condition,
    cm.encounter_count,
    ROUND(cm.encounter_count::NUMERIC * 100.0 / NULLIF(t.grand_total_encounters, 0), 2) AS pct_of_encounters,
    ROUND(cm.total_billing_usd, 2) AS total_billing_usd,
    ROUND(cm.avg_billing_usd, 2) AS avg_billing_usd,
    ROUND(cm.median_billing_usd, 2) AS median_billing_usd,
    ROUND(cm.avg_los_days, 2) AS avg_los_days,
    ROUND((cm.total_billing_usd / NULLIF(t.grand_total_billing_usd, 0)) / 
          (cm.encounter_count::NUMERIC / NULLIF(t.grand_total_encounters, 0)), 3) AS cost_to_volume_ratio
FROM condition_metrics cm
CROSS JOIN totals t
ORDER BY cm.total_billing_usd DESC;

Ranking: DENSE_RANK() & PARTITION BY

Business Question: Who are the top 3 admitting physicians by inpatient caseload within active hospital facilities?

Uses ROW_NUMBER() OVER (PARTITION BY hospital_name ORDER BY COUNT(*) DESC) to rank treating physicians within each medical center.

Source File: sql/09_providers.sql
Techniques: Window Partitioning, DENSE_RANK
sql/09_providers.sql (Excerpt: Top Physicians per Facility) 
WITH top_hospitals AS (
    SELECT hospital_name
    FROM healthcare.admissions
    GROUP BY hospital_name
    HAVING COUNT(admission_record_id) >= 5
    ORDER BY COUNT(admission_record_id) DESC
    LIMIT 5
),
physician_workload AS (
    SELECT 
        a.hospital_name,
        a.doctor_name,
        COUNT(a.admission_record_id)         AS encounters_handled,
        ROUND(SUM(a.billing_amount), 2)      AS doctor_total_billing_usd,
        ROUND(AVG(a.billing_amount), 2)      AS doctor_avg_billing_usd,
        ROUND(AVG(a.length_of_stay_days), 2) AS doctor_avg_los_days,
        ROW_NUMBER() OVER (
            PARTITION BY a.hospital_name 
            ORDER BY COUNT(a.admission_record_id) DESC, SUM(a.billing_amount) DESC
        ) AS physician_rank_in_facility
    FROM healthcare.admissions a
    INNER JOIN top_hospitals th ON a.hospital_name = th.hospital_name
    GROUP BY a.hospital_name, a.doctor_name
)
SELECT 
    hospital_name,
    physician_rank_in_facility,
    doctor_name,
    encounters_handled,
    doctor_total_billing_usd,
    doctor_avg_billing_usd,
    doctor_avg_los_days
FROM physician_workload
WHERE physician_rank_in_facility <= 3
ORDER BY hospital_name, physician_rank_in_facility;

Architectural SQL: Chained CTE Benchmarking

Business Question: How does each medical condition's average charge deviate from the overall enterprise hospital baseline?

Computes enterprise averages in CTE 1, condition metrics in CTE 2, and calculates variance deltas and percentage deviations in the final projection.

Source File: sql/12_cte_analysis.sql
sql/12_cte_analysis.sql (Excerpt) 
WITH enterprise_baseline AS (
    SELECT 
        COUNT(*)                             AS grand_total_encounters,
        ROUND(AVG(billing_amount), 2)        AS enterprise_avg_billing,
        ROUND(AVG(length_of_stay_days), 2)   AS enterprise_avg_los
    FROM healthcare.admissions
    WHERE is_negative_billing = FALSE
),
condition_performance AS (
    SELECT 
        medical_condition,
        COUNT(admission_record_id)           AS condition_encounters,
        ROUND(SUM(billing_amount), 2)        AS condition_total_billing,
        ROUND(AVG(billing_amount), 2)        AS condition_avg_billing,
        ROUND(AVG(length_of_stay_days), 2)   AS condition_avg_los
    FROM healthcare.admissions
    WHERE is_negative_billing = FALSE
    GROUP BY medical_condition
)
SELECT 
    cp.medical_condition,
    cp.condition_encounters,
    cp.condition_avg_billing,
    eb.enterprise_avg_billing,
    ROUND(cp.condition_avg_billing - eb.enterprise_avg_billing, 2) AS billing_diff_from_enterprise,
    ROUND(((cp.condition_avg_billing - eb.enterprise_avg_billing) * 100.0 / 
           NULLIF(eb.enterprise_avg_billing, 0)), 2) AS billing_variance_pct
FROM condition_performance cp
CROSS JOIN enterprise_baseline eb
ORDER BY cp.condition_avg_billing DESC;

Strategic Advisory

Verified Quantitative Business Insights

Structured following the Senior Data Analyst standard: Finding → Evidence → Business Implication → Recommendation → Limitation.

1

Upper Quartile Charge Concentration

Finding

While patient volume is evenly divided, gross financial charges are heavily concentrated in Quartile 4 ($Q_4$), with an average charge 6.2x higher than $Q_1$.

SQL Evidence: $Q_4$ ($N = 13,742$) averages $43,997.56 and absorbs $604.6M (43.06% of total charges), compared to $7,075.36 in $Q_1$. Top 5% ($P_{95} \ge \$47,638.27$) absorb $134.8M.
Implication & Recommendation

Pre-bill clinical documentation review should focus primarily on claims > $37,820 ($Q_4$) to preempt high-dollar denials from commercial payers.

Limitation

Dataset lacks itemized revenue codes (OR, ICU, pharmacy); cannot identify specific clinical cost drivers.

2

Balanced Payer Market Share

Finding

Gross hospital charges and admissions are distributed evenly across five major insurance carriers without single-payer concentration risk.

SQL Evidence: Cigna (20.27%, $284.3M), Medicare (20.08%, $282.9M), Blue Cross (19.93%, $280.4M), UnitedHealthcare (20.04%, $279.9M), Aetna (19.69%, $276.5M).
Implication & Recommendation

Maintains strong bargaining leverage during contractual renegotiation cycles. Recommend implementing payer-specific denial velocity tracking.

Limitation

Represents gross chargemaster prices, not net collected cash after contractual allowances.

3

Senior Cohort Bed Occupancy

Finding

Inpatient admissions are heavily driven by older adults, with patients aged 65 and older representing the largest single demographic cohort.

SQL Evidence: 65+ seniors account for 16,096 admissions (29.28%), generating $409.3M in gross charges. Pediatric cases (<18) account for only 0.21% (116 cases).
Implication & Recommendation

Expand specialized geriatric care coordination pathways and post-acute discharge navigators (skilled nursing / home health).

Limitation

Lacks Medicare supplemental coverage details or clinical frailty indices.

4

Cardiometabolic Care Volume

Finding

Cardiometabolic conditions (Diabetes, Obesity, Hypertension) account for exactly half of all hospital admissions and gross charges.

SQL Evidence: Together they represent 50.05% of volume (27,513 admissions) and $705,872,154.71 in gross charges (Diabetes $236.5M, Obesity $236.0M, Hypertension $233.4M).
Implication & Recommendation

Invest in integrated cardiometabolic chronic care outpatient programs to prevent unplanned acute admissions.

Limitation

Uniform distribution (~16.6% per condition) reflects synthetic generation parameters.

5

Decoupled Bed-Day Charge Duration

Finding

Inpatient stay duration (ALOS = 15.50 days) exhibits zero descriptive correlation with billed charges ($r = 0.0003$).

SQL Evidence: Stays strictly span 1 to 30 days. Average billing for 1-day stay is $25,512.43, virtually identical to 30-day stay ($25,488.19).
Implication & Recommendation

Must communicate clearly to leadership that this zero correlation is an artifact of synthetic generation, preventing flawed operational conclusions.

Limitation

Generator assigned billing amounts and length of stay independently.

Scientific Governance

Methodology & Critical Limitations

Sound data analysis requires transparently communicating assumptions, data processing standards, and clinical boundaries.

ELT Staging-to-Production

Raw CSV records are ingested losslessly into permissive staging_admissions text tables before deterministic transformation into admissions with generated surrogate keys (BIGSERIAL) and B-Tree indexes.

The Readmission Fallacy (Why Out of Scope)

The dataset lacks an Enterprise Master Patient Index (EMPI) or Social Security Number. Grouping by patient_name creates false readmission pairings. 30-day readmission calculations are formally declared out of scope.

Chargemaster vs. Net Collections

billing_amount represents gross hospital chargemaster list charges, not actual net cash received after commercial insurer contractual discounts or Medicare fee schedule adjustments.

Reproducibility

How to Reproduce This Project

Every script in this repository is idempotent and designed to execute sequentially in PostgreSQL or via the automated Python test harness.

01
Clone Repository

Clone the project files from GitHub to your local environment:

git clone https://github.com/NgKthy/prj-healthcare-data-analysis.git
cd prj-healthcare-data-analysis
02
Initialize PostgreSQL

Run schema setup and staging table creation:

psql -U postgres -f sql/01_setup.sql
psql -U postgres -f sql/02_staging.sql
03
Import & Clean

Copy raw CSV and execute deduplication ELT:

\copy healthcare.staging_admissions FROM 'data/raw/healthcare_dataset.csv' WITH (FORMAT csv, HEADER true);
psql -U postgres -f sql/04_cleaning.sql
04
Run Validation Suite

Execute analytical scripts (05 to 19) and assertion test suite:

psql -U postgres -f sql/20_validation.sql
# Or run Python test harness:
python scripts/run_all_tests.py
